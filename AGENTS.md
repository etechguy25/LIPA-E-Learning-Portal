# Project Rules & Instructions

- **No Sample / Mock Data**: Always keep the application clean and empty of sample data unless the user explicitly inputs it. Do not inject pre-populated dummy courses, mock students, fake grades, dummy transactions, or sample analytics into the app.
- **Dynamic & User-Driven**: Data models, statistics, charts, tables, and financial reconciliations must dynamically calculate from actual user-created records or remain at clean zero / empty states with helpful empty prompts.
- **Empty State UX**: All views (tables, rosters, charts, directories) must support elegant empty state messages prompting the user to create their first item.
